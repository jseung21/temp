차세대 데이터 플랫폼을 위한 ETL/ELT 아키텍처 설계 보고서

데이터 수집, 처리, 분석 환경의 현대화 전략

​

1. 데이터 통합 패러다임의 변화와 레거시의 한계

전통적인 ETL(Extract, Transform, Load) 프로세스는 정형화된 데이터를 주기적으로 처리하는 배치 중심 환경에 최적화되어 있었습니다. 그러나 현대의 데이터 생태계는 실시간 스트리밍, 비정형 로그 등 방대한 소스로 구성되어 있으며, 기존 SW는 다음과 같은 한계를 노출하고 있습니다.

  • 확장성 부족: 데이터 볼륨 확장 시 수평적 확장이 불가능하여 성능 병목 현상 발생.
  • 유연성 결여: 분석 요구사항 변경 시 파이프라인 전체를 재설계해야 하는 구조적 문제.
  • 안정성 이슈: 특정 처리 서버의 성능 한계가 전체 시스템의 가용성에 영향.
​

2. ETL vs ELT: 기술적 비교 분석

차세대 아키텍처의 핵심은 클라우드 네이티브의 탄력적 자원을 활용하는 ELT 모델로의 전환입니다.

비교 항목 ETL (Extract, Transform, Load) ELT (Extract, Load, Transform)
변환 위치 별도의 중간 처리 서버 타깃 데이터 웨어하우스 내부
데이터 보존 변환된 결과만 저장 (원시 데이터 손실 가능) 원시 데이터를 그대로 보존 (재처리 가능)
처리 성능 데이터 양 증가 시 확장성 한계 분산 컴퓨팅(MPP) 활용으로 대규모 처리 유리
데이터 유형 주로 정형 데이터에 최적화 정형, 반정형, 비정형 모두 수용 가능
​

3. 클라우드 네이티브 ETL 엔진 및 분산 처리

서버리스 통합 서비스

  • AWS Glue: 서버리스 환경에서 인프라 관리 부담 없이 자원 자동 스케일링 및 메타데이터 중앙 관리.
  • Google Dataflow: 배치와 스트리밍을 하나의 모델로 처리하며 워크로드에 따른 정교한 자동 확장 지원.

고성능 분산 엔진

Apache Spark는 인메모리 분산 처리를 통해 배치 성능을 극대화하며, Apache Flink는 밀리초 단위의 지연 시간으로 '진정한 실시간' 처리를 구현합니다.

​

4. 실시간 처리를 위한 아키텍처 패턴

Lambda Architecture: 배치 레이어(정확성)와 스피드 레이어(실시간성)를 이중으로 운영하여 결함 허용 능력을 확보합니다.

Kappa Architecture: "모든 데이터는 스트림이다"라는 철학 하에 단일 스트림 처리 엔진으로 시스템을 단순화합니다.

​

5. 데이터 레이크하우스와 테이블 포맷 (Apache Iceberg)

기존 데이터 레이크의 한계를 극복하기 위해 Apache Iceberg 테이블 포맷을 도입하여 레이크하우스를 구축할 것을 권장합니다.

  • ACID 트랜잭션: 데이터 일관성 보장 및 작업 실패 시 자동 롤백.
  • 히든 파티셔닝: 수동 파티션 관리 없이 쿼리 패턴에 따른 최적화.
  • 스키마 에볼루션: 데이터 재작성 없는 간편한 컬럼 업데이트.
​

6. dbt 및 오케스트레이션 고도화

변환 로직을 소프트웨어 엔지니어링 관점에서 관리하는 dbt를 도입하여 데이터 품질을 보증해야 합니다. 또한, Airflow와 같은 오케스트레이션 도구를 통해 수천 개의 파이프라인 의존성을 시각화하고 안정적으로 조율합니다.

​

7. 성능 최적화 가이드라인

  • 파티셔닝 전략: 파티션당 128MB~256MB 크기를 유지하도록 설정 (N \approx \text{Total Data Size} / 128 \text{ MB}).
  • 데이터 스큐 방지: Salting 기법을 활용하여 특정 키에 데이터가 몰리는 현상 방지.
  • 데이터 관측성: Monte Carlo 등 도구를 활용해 신선도, 볼륨, 스키마 변경 등을 실시간 모니터링.
​

8. 최종 통합 아키텍처 제안 (Modern Data Stack)

  1. 수집: Airbyte 또는 Kafka Connect를 통한 실시간/배치 수집
  2. 저장: Cloud S3 + Apache Iceberg 기반 레이크하우스
  3. 변환: dbt를 활용한 SQL 기반 선언적 변환
  4. 조율: Managed Airflow를 통한 전사 워크플로우 관리
  5. 관측: 데이터 품질 및 신뢰성 탐지 엔진 도입
